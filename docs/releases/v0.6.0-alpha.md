# v0.6.0-alpha

Fecha: 2026-07-02 (Application Shell) → 2026-07-03 (Module System + Dashboard Foundation + TECH-001)

## Resumen

Segunda versión alpha. Sobre el Design System Core (v0.3.0-alpha) se construye el Application
Shell, el Module Registry y el primer módulo de producto real: el Dashboard. Cierra además
TECH-001, un bug de integración de Tailwind v4 en el monorepo que afectaba la generación de
utilidades usadas por `packages/ui`.

## Sprints incluidos

- Sprint 0.4 — Application Shell: `AppShell`, `Workspace`, navegación, `WorkspaceStore`
  (Zustand).
- Sprint 0.5 — Module System: Module Registry (`apps/web/modules/module-registry`), contrato de
  módulos, placeholders para `dashboard`, `profile`, `projects`, `mission-log`, `capabilities`,
  `lab`, `communication`.
- Sprint 0.6 — Dashboard Foundation: primer módulo real (6 widgets: `Hero`, `QuickStats`,
  `CurrentFocus`, `RecentActivity`, `QuickNavigation`, `SystemStatus`), datos estáticos tipados
  (`apps/web/data/dashboard.ts`).
- TECH-001 — Fix de integración Tailwind v4 en monorepo (ver
  [ADR-005](../../decisions/ADR-005-tailwind-v4-monorepo.md)).

## Funcionalidades

- `AppShell` + `Workspace` como contenedor de navegación entre módulos.
- Module Registry: mecanismo de registro/resolución de módulos, sin acoplar `Workspace` a
  módulos concretos.
- `WorkspaceStore` (Zustand) como única fuente de estado de navegación entre módulos.
- Dashboard funcional: Hero con CTA a Projects, 5 métricas rápidas, foco actual, actividad
  reciente (máx. 5 items), navegación rápida a los 5 módulos restantes, 6 indicadores de estado
  del sistema.
- `DashboardModule` como único consumidor autorizado de `apps/web/data/dashboard.ts`; widgets
  puros y presentacionales, reciben datos solo por props.
- Generación correcta de utilidades de Tailwind v4 para `packages/ui` en todo el monorepo
  (`@source` explícito en `packages/config/tailwind.css`).

## Métricas

- 124/124 tests pasan (68 en `apps/web`, 56 en `packages/ui`).
- Cero errores/warnings de ESLint en `web` y `ui`.
- Cero errores de TypeScript (`tsc --noEmit`).
- Cero violaciones de accesibilidad (`vitest-axe`) por widget y en integración.
- Build de producción (`next build`) exitoso.

## Deuda técnica conocida

- `CurrentFocus` muestra estado como texto (`Typography`) hasta que exista un primitive `Badge`
  en el Design System.
- Deuda técnica heredada de v0.3.0-alpha (`Tooltip`, tokens de opacidad, tipografía fluida,
  breakpoints responsive completos, `Skeleton`, `VisuallyHidden`) — sin cambios en este release.
